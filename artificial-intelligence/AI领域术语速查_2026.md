## 一、快速认识整体框架

当前 AI 的一个重要发展趋势，是从“根据输入生成内容”逐步发展为“围绕目标进行推理、调用工具和执行任务”。可以用下面的**简化框架**把常见概念串联起来：

```text
AI（人工智能）
└── Machine Learning（机器学习）
    └── Deep Learning（深度学习）
        └── Foundation Model（基础模型）
            ├── LLM（大语言模型）
            │   ├── Transformer / Attention / Token
            │   ├── Pre-training / Post-training
            │   ├── Reasoning Model / Test-time Compute
            │   └── Tool Calling / RAG / Memory
            │       └── AI Agent / Multi-agent
            │           ├── AI Coding
            │           ├── Deep Research / AI for Science
            │           └── Computer Use
            └── Multimodal Models（多模态模型）
                ├── VLM（视觉语言模型）
                ├── World Model（世界模型）
                └── VLA / Embodied AI（视觉语言动作 / 具身智能）

基础设施与横向能力：GPU、Quantization、Evaluation、Alignment、Safety 等
```

**注意**：这是一幅用于建立直觉的概念图，并非严格的分类树。例如，生成式 AI 不局限于语言模型；世界模型也不一定建立在大语言模型之上；Agent 是系统设计方式，而不是某种固定的模型架构。

## 二、AI 基础概念

| 英文术语 | 中文名称 | 简明解释 |
|---|---|---|
| Artificial Intelligence (AI) | 人工智能 | 研究和构建具有感知、学习、推理、决策等能力的计算系统。 |
| Machine Learning (ML) | 机器学习 | 通过数据学习规律，而不是完全依赖人工指定每一条规则。 |
| Deep Learning (DL) | 深度学习 | 主要利用多层神经网络学习复杂表示，是现代 AI 的重要技术基础。 |
| Generative AI (GenAI) | 生成式人工智能 | 能够生成文本、图像、音频、视频、代码等内容的 AI。 |
| Foundation Model | 基础模型 | 在大量数据上训练，可以适配不同下游任务的通用模型。 |
| Large Language Model (LLM) | 大语言模型 | 以语言建模为核心，能够理解和生成自然语言、代码等序列内容的模型。 |
| Small Language Model (SLM) | 小语言模型 | 相对较小的语言模型，通常更关注运行成本、速度和本地部署。 |
| Frontier Model | 前沿模型 | 在某些关键能力或评测上位于当前领先水平的模型。 |
| Artificial General Intelligence (AGI) | 通用人工智能 | 设想能在广泛认知任务上表现出高度通用能力的 AI；目前没有公认的统一判定标准。 |
| Artificial Superintelligence (ASI) | 超级人工智能 | 假设在广泛认知能力上超过人类水平的 AI，主要属于未来发展讨论。 |

**理解要点**：LLM 指模型类型；聊天产品则可能把 LLM 与搜索、记忆、语音、文件处理和工具调用等功能结合在一起。

## 三、大模型的架构与工作机制

| 英文术语 | 中文名称 | 简明解释 |
|---|---|---|
| Transformer | Transformer 架构 | 一类基于注意力机制的神经网络架构，是许多现代大语言模型的基础。 |
| Attention | 注意力机制 | 根据上下文动态计算不同信息位置之间的关联与权重。 |
| Token | 词元 | 模型处理文本的基本单位，可能是单字、词、词的一部分或其他符号。 |
| Context Window | 上下文窗口 | 模型在一次处理过程中可接收的上下文长度上限。 |
| Embedding | 嵌入向量 | 把文本、图像等对象表示成数值向量，方便表示相似性及其他关系。 |
| Mixture of Experts (MoE) | 混合专家模型 | 使用多个专家网络，并通常为每个输入只激活部分专家，以平衡容量和计算量。 |
| Autoregressive Generation | 自回归生成 | 根据已有序列依次预测后续 Token 的生成方式。 |
| Scaling Laws | 规模定律 | 描述模型性能与模型规模、数据规模和计算资源等之间的经验关系。 |

**直观理解 MoE**：好比系统中存在不同的“专家模块”，每个输入只让其中部分模块参与处理，而不是每次调用所有模块。

## 四、模型训练与能力提升

| 英文术语 | 中文名称 | 简明解释 |
|---|---|---|
| Pre-training | 预训练 | 通过大规模数据学习通用的语言、知识和表征规律。 |
| Post-training | 后训练 | 在预训练后进一步改进指令遵循、推理表现、偏好对齐等能力。 |
| Fine-tuning | 微调 | 基于已经训练好的模型，再用特定数据继续训练。 |
| Supervised Fine-tuning (SFT) | 监督微调 | 使用输入与目标输出配对的示例来训练模型。 |
| Reinforcement Learning from Human Feedback (RLHF) | 人类反馈强化学习 | 依据人类偏好或评价信号，通过强化学习改进模型行为。 |
| Direct Preference Optimization (DPO) | 直接偏好优化 | 直接利用回答之间的偏好比较优化模型，避免传统 RLHF 的部分复杂流程。 |
| Reinforcement Learning with Verifiable Rewards (RLVR) | 可验证奖励强化学习 | 用可客观检验的结果作为奖励，例如答案正确与否、代码是否通过测试。 |
| Group Relative Policy Optimization (GRPO) | 组相对策略优化 | 利用同一问题的多个候选输出之间的相对奖励进行策略优化的方法。 |
| Low-Rank Adaptation (LoRA) | 低秩适配 | 以较少的新增可训练参数来适配模型，降低微调资源需求。 |
| Knowledge Distillation | 知识蒸馏 | 让较小的学生模型向较大的教师模型学习。 |
| Synthetic Data | 合成数据 | 由模型或程序生成、而非完全由真实观察或人工标注得到的数据。 |

**一个核心区别**：预训练侧重通用能力的形成；后训练侧重让已有能力更好地服务特定任务、推理要求和行为规范。

## 五、推理能力与测试时计算

| 英文术语 | 中文名称 | 简明解释 |
|---|---|---|
| Reasoning Model | 推理模型 | 针对数学、编程、多步骤分析和规划等复杂任务专门强化的模型。 |
| Chain of Thought (CoT) | 思维链 | 把复杂问题拆成中间步骤的推理策略或表示方式。 |
| Test-time Compute | 测试时计算 | 模型在回答一个问题时所使用的计算资源，与训练时的计算投入相区分。 |
| Inference-time Scaling | 推理时扩展 | 通过增加推理阶段的计算量、探索或验证步骤，改善复杂任务表现。 |
| Self-consistency | 自一致性 | 对同一问题产生多条推理路径，再比较或汇总其结果。 |
| Verifier | 验证器 | 检查模型答案、推理步骤或执行结果是否符合标准的程序或模型。 |

**注意**：“推理模型”（reasoning model）的 reasoning 与“模型推理部署”（inference）中的 inference 不是同一个概念。增加思考步骤也并不保证正确。

## 六、智能体与工具生态

| 英文术语 | 中文名称 | 简明解释 |
|---|---|---|
| AI Agent | AI 智能体 | 围绕目标进行规划、使用工具、采取行动和处理反馈的 AI 系统。 |
| Agentic AI | 智能体式 AI | 强调系统具有一定的自主规划与行动能力的技术方向。 |
| Tool Calling | 工具调用 | 模型请求外部搜索、代码执行器、数据库或软件工具完成操作。 |
| Function Calling | 函数调用 | 按规定的函数名和参数格式请求执行操作，是工具调用的一种常见形式。 |
| Computer Use | 计算机操作 | AI 通过界面交互或接口控制浏览器、桌面程序等软件。 |
| Multi-agent System | 多智能体系统 | 多个 Agent 分工完成检索、分析、执行和评估等子任务。 |
| Orchestration | 智能体编排 | 协调多个步骤、工具或 Agent 的职责、顺序、状态与交互。 |
| Model Context Protocol (MCP) | 模型上下文协议 | 让 AI 应用以标准化方式连接外部工具、资源和服务的开放协议。 |
| Agent2Agent Protocol (A2A) | 智能体间协议 | 支持不同 Agent 或系统之间交换信息并开展协作的协议。 |
| Agent Skills | 智能体技能 | 将任务说明、资源、脚本和操作规范组织成可复用的技能单元。 |
| Agent Memory | 智能体记忆 | 保存和检索任务状态、用户相关信息与历史上下文的机制。 |
| Retrieval-Augmented Generation (RAG) | 检索增强生成 | 先从文档或知识库检索信息，再把检索结果交给模型辅助生成回答。 |
| Deep Research | 深度研究 | 多轮搜索、阅读、整理与综合资料，形成较系统研究成果的 AI 工作流程。 |
| Human-in-the-loop (HITL) | 人在回路中 | 在自动化流程中加入人工审查、纠错、批准或接管。 |
| Prompt Engineering | 提示词工程 | 设计和优化模型输入的指令、示例和表达方式。 |
| Context Engineering | 上下文工程 | 系统地组织指令、历史信息、工具反馈和外部知识，让模型拿到完成任务所需的上下文。 |

**示例**：当用户提出“检索某领域最新论文并整理成报告”时，Agent 可能先搜索，再读取论文，随后生成结构化综述，必要时调用程序检查引用或分析数据。

**Agent、MCP、A2A、Skills 如何区分？**

- **Agent**：负责完成目标的执行主体或系统。
- **MCP**：解决 Agent/模型应用如何连接工具和数据的问题。
- **A2A**：解决不同 Agent 如何相互通信、协作的问题。
- **Skills**：提供完成特定任务时可复用的流程和知识。
- **RAG**：解决如何把外部检索到的信息提供给生成模型的问题。

这几者可以组合使用，但一个 Agent 并不必须同时包含全部组件。

## 七、AI 编程与软件开发

| 英文术语 | 中文名称 | 简明解释 |
|---|---|---|
| AI Coding Assistant | AI 编程助手 | 辅助编写、解释、补全、修改和调试代码的工具。 |
| Coding Agent | 编程智能体 | 能够跨文件修改项目、执行命令、运行测试和迭代修复问题的 Agent。 |
| Vibe Coding | 氛围编程 | 主要通过自然语言描述目标并让 AI 生成代码，开发者通过反馈推动实现。 |
| Agentic Engineering | 智能体式软件工程 | 将 Agent 纳入受约束的开发流程，强调规范、测试、代码审查与责任归属。 |
| AI IDE | AI 集成开发环境 | 将编辑器、项目理解、对话与 AI 开发能力融合的软件环境。 |
| Spec-driven Development | 规范驱动开发 | 在实现之前先定义需求、设计约束和验收标准，再据此开发或让 AI 执行。 |

**区别**：Vibe Coding 更偏向快速把想法实现出来；Agentic Engineering 更强调工程质量、验证和可维护性。二者不是完全互斥的技术类别。

## 八、多模态、世界模型与具身智能

| 英文术语 | 中文名称 | 简明解释 |
|---|---|---|
| Multimodal AI | 多模态 AI | 联合处理文字、图像、语音、视频等不同类型信息。 |
| Vision-Language Model (VLM) | 视觉语言模型 | 同时处理视觉和语言信息，例如看图问答、视觉描述。 |
| Diffusion Model | 扩散模型 | 学习从噪声逐步生成目标数据的一类生成模型。 |
| Flow Matching | 流匹配 | 学习一个连续的变化过程，将简单分布映射为目标数据分布的建模方法。 |
| Text-to-Video | 文生视频 | 根据文字描述生成视频。 |
| Speech-to-Speech | 语音到语音 | 以语音作为输入，直接生成语音回应的交互方式。 |
| World Model | 世界模型 | 建模环境状态及其变化，并预测行动可能造成的后果。 |
| Embodied AI | 具身智能 | 研究智能体如何通过传感器、身体与行动同物理环境交互。 |
| Vision-Language-Action Model (VLA) | 视觉—语言—动作模型 | 结合视觉、语言指令和动作输出，常用于机器人控制。 |
| Physical AI | 物理 AI | 强调面向现实物理环境的感知、理解、预测和行动能力。 |

**直观理解**：VLM 可以“看图回答问题”；VLA 的目标则是进一步把视觉与语言理解转化成动作。世界模型侧重理解或模拟“环境接下来可能发生什么”。

## 九、算力、部署、评估与安全

| 英文术语 | 中文名称 | 简明解释 |
|---|---|---|
| Inference | 模型推理／推理部署 | 用训练完成的模型处理新输入并产生结果；不等同于 reasoning。 |
| GPU / AI Accelerator | 图形处理器／AI 加速器 | 适于执行大规模并行矩阵等计算的硬件，是 AI 训练和部署的关键基础设施。 |
| Quantization | 量化 | 用更低精度表示权重或进行运算，通常用于降低模型的存储与计算成本。 |
| KV Cache | 键值缓存 | 在序列生成时缓存注意力相关的中间结果，避免大量重复计算。 |
| Latency | 延迟 | 从请求发出到响应产生需要的时间。 |
| Throughput | 吞吐量 | 系统单位时间能处理的任务、请求或 Token 数。 |
| On-device AI | 端侧 AI | 让 AI 模型直接运行在手机、个人电脑等终端设备上。 |
| Open-weight | 开放权重 | 发布训练完成后的模型参数；并不一定公开训练数据或完整训练流程。 |
| Open-source AI | 开源 AI | 按相应开放定义和许可开放 AI 所需的资源与权利；一般不等于仅发布模型权重。 |
| Hallucination | 幻觉 | AI 生成看起来合理、实际上错误或缺乏证据支持的内容。 |
| Prompt Injection | 提示词注入 | 利用恶意输入或外部材料试图影响系统行为或覆盖原有指令。 |
| Alignment | AI 对齐 | 使 AI 行为更符合预期目标、指令、价值规范与安全约束。 |
| Benchmark / Evaluation (Eval) | 基准评测／评估 | 利用测试任务、指标和实验流程衡量模型能力、可靠性与安全表现。 |
| Red Teaming | 红队测试 | 主动模拟攻击、异常输入或风险场景，以发现系统弱点。 |
| AI Slop | AI 垃圾内容 | 通常指大批量生产、低质量且缺乏实质价值的 AI 生成内容。 |
| Sovereign AI | 主权 AI | 强调国家或地区对 AI 模型、数据、算力与治理能力的自主掌控。 |

**理解要点**：模型能力强并不意味着系统一定可靠。实际部署还需要关注成本、延迟、评估、访问控制和安全。

## 十、AI for Science：AI 与科学研究

| 英文术语 | 中文名称 | 简明解释 |
|---|---|---|
| AI for Science | AI 赋能科学研究 | 用 AI 辅助或推动物理、化学、生物、医学等领域的科学研究。 |
| Scientific Foundation Model | 科学基础模型 | 以科学领域数据训练、能够迁移到多种科学任务的基础模型。 |
| AI Scientist | AI 科学家 | 尝试自动化问题提出、实验设计、数据分析、代码编写或报告撰写的系统。 |
| Self-driving Lab | 自主实验室 | 结合 AI、仪器自动化和反馈循环，自主设计并执行实验。 |
| Digital Twin | 数字孪生 | 为真实对象或过程建立可更新的数字模型，以进行模拟、监测和预测。 |
| Causal AI | 因果人工智能 | 将因果推断与机器学习结合，研究干预、因果关系和反事实问题。 |
| Neuro-symbolic AI | 神经符号 AI | 将神经网络的统计学习与规则、逻辑等符号推理方法结合。 |

**科研视角**：AI 可以帮助发现候选规律、生成假设和提高研究效率，但“生成一个合理假设”与“用可靠证据证实该假设”是不同的事情。

## 十一、常见易混淆概念

| 概念 A | 概念 B | 核心差别 |
|---|---|---|
| AI | LLM | AI 是宽泛领域；LLM 是其中一类模型。 |
| LLM | AI Agent | LLM 是模型；Agent 通常是整合模型、工具、状态和执行逻辑的系统。 |
| Generative AI | Agentic AI | 前者强调生成内容；后者强调规划和执行任务。两者可重叠。 |
| Reasoning | Inference | 前者强调求解、分析和逻辑推理能力；后者通常指训练后的模型计算或运行。 |
| Pre-training | Post-training | 前者建立广泛基础能力；后者进一步适配指令、偏好或特定能力。 |
| SFT | RLHF / RLVR | SFT 主要从示范答案学习；RLHF/RLVR 通过奖励信号优化行为。 |
| RAG | Fine-tuning | RAG 在使用时引入外部检索内容；微调通过训练改变模型参数。 |
| MCP | A2A | MCP 面向模型应用与工具、资源连接；A2A 面向 Agent 之间的协作。 |
| Prompt Engineering | Context Engineering | 前者侧重提示指令设计；后者涵盖整个输入上下文的获取与组织。 |
| Open-weight | Open-source AI | 发布权重不代表完整满足开源 AI 的相关要求。 |
| VLM | VLA | VLM 重视视觉和语言理解；VLA 还将动作输出纳入建模。 |
| World Model | Digital Twin | 前者泛指环境动态或变化规律的模型；后者通常对应某个具体真实系统的数字映射。 |
| Coding Assistant | Coding Agent | 前者以辅助开发者为主；后者通常可以自主执行跨步骤开发工作。 |

## 十二、建议优先掌握的术语

如果只想先记住十个，推荐按如下顺序：

1. **LLM**：大语言模型——理解当前语言 AI 的核心载体。
2. **Transformer**：理解主流大模型的基本架构。
3. **Reasoning Model**：理解为什么新模型越来越强调复杂问题求解。
4. **RLVR**：了解可验证任务如何帮助训练推理能力。
5. **AI Agent**：理解 AI 从回答问题向执行任务的转变。
6. **RAG**：理解如何把外部资料提供给模型。
7. **MCP**：理解 Agent 和外部工具的标准化连接。
8. **Multi-agent**：理解多个智能体之间的协作。
9. **World Model**：理解对环境变化和后果的建模。
10. **VLA**：理解 AI 如何从多模态感知走向机器人行动。

如果关注科学研究，可在此基础上优先补充 **AI for Science、Scientific Foundation Model、Causal AI、AI Scientist**。
